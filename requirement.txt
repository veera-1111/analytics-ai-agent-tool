FEDEX AI ANALYTICS CHATBOT POC – FULL SYSTEM DESIGN & IMPLEMENTATION SPECIFICATION
OBJECTIVE
Build a fully dockerized AI-powered logistics analytics chatbot platform that simulates a FedEx-style operational analytics system using synthetic logistics data.

The application should allow users (operations managers, sales teams, leadership teams) to ask natural language business questions and dynamically generate analytics reports.

The reports should:

be generated conversationally

support follow-up clarification questions

render enterprise-style tables/charts

generate permanent report URLs

always show real-time data when revisited

support PDF/Excel export

run entirely in Docker

deploy into AWS

This is a POC/MVP, NOT a production-grade enterprise system.

HIGH LEVEL REQUIREMENTS
Core Features

Users should ask questions like:

ADDITIONAL INTEGRATION REQUIREMENTS — PHP APPLICATION EMBEDDED MODE
IMPORTANT ARCHITECTURE CHANGE
The AI analytics chatbot platform is NOT a standalone application anymore.

It must be embedded into an existing PHP web application.

The PHP application is the primary host application and already handles:

authentication

user sessions

navigation

left panel/menu system

user management

The AI analytics platform should behave as a modular embedded analytics component inside the PHP ecosystem.

UPDATED SYSTEM ARCHITECTURE
Existing PHP Application
↓
Embedded AI Chat Widget (React/Next.js)
↓
FastAPI Backend
↓
AI Workflow + PostgreSQL

The AI application must trust authentication/session information coming from PHP.

INTEGRATION REQUIREMENTS
1. EMBEDDED CHATBOT WIDGET
The chatbot UI must be embeddable inside PHP pages.

Preferred integration methods:

iframe embedding
OR

JavaScript widget injection

Preferred approach:

iframe-based embedding for simplicity and isolation.

Example:

<iframe
    src="https://ai-analytics.company.com/chat"
    width="100%"
    height="100%"
    frameborder="0">
</iframe>
However, authentication/session data must still be shared securely.

2. PHP SESSION INTEGRATION
The AI backend MUST receive authenticated user information from the PHP session.

The existing PHP application is the source of truth for authentication.

DO NOT implement separate login screens in the AI app.

3. RECOMMENDED AUTHENTICATION FLOW
Preferred Flow
PHP App
↓
Creates signed JWT token
↓
Passes token to embedded AI widget
↓
FastAPI validates JWT
↓
User context established

JWT PAYLOAD REQUIREMENTS
The PHP application should generate JWT tokens containing:

{
"user_id": 123,
"username": "john.doe",
"email": "john@example.com",
"role": "manager",
"region": "South",
"exp": 9999999999
}

FASTAPI AUTH REQUIREMENTS
Implement JWT middleware in FastAPI.

Requirements:

validate token signature

extract user context

attach user info to request context

use role/region filters in reports
